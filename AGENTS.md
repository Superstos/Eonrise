# Eonrise agent instructions

Eonrise is a private deep-research router and memory base.

**Its point is a shortcut to ideas.** A problem that is new or half solved in one field is
often mature in another. Eonrise finds those fields so their solutions can be ported.
Papers from distant fields are the product: before calling any result off-topic or a run
"noise", ask of each distant paper what problem it solved that has the same shape as yours.
The on-topic count measures shared words, not usefulness.

## Default use

Use Eonrise as the default depth layer for broad work: education design, invention, architecture, strategy, multi-field questions, and complaints about broad-answer quality. Do not wait for the user to say “use Eonrise.”

Skip only closed-form facts, simple calculations, rewriting, translation, casual chat, or an explicit fast/surface request.

## Research behavior

1. Prefer existing research bundles before fresh lookup.
2. Run the router and inspect gaps, not only top terms.
3. In assistant mode, search recommended missing angles, append grounded records, and rerun.
4. Preserve URLs, paper IDs, queries, and accurate summaries.
5. Never turn an unsupported generated phrase into a fact.
6. Stop when checks pass or report the unresolved gap honestly.

## Delivery behavior

Research deeply internally; answer compactly externally.

- Do not dump tool traces, search loops, paper lists, or ontology maps unless asked.
- Lead with the answer or decision.
- Include only evidence that changes the conclusion.
- Default broad-answer budget: roughly 120–250 words.
- A complaint triggers research and a behavior fix, not a long apology.
