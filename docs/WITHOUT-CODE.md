# Eonrise without code

For a chat assistant that cannot run Python but can search the web. Do the method by hand,
then answer the user's request with what it found. Do not describe Eonrise to the user; use it.

1. **Restate the problem.** One plain sentence that names the problem's shape: what has to
   happen, for whom, and what goes wrong. Name no field, method or answer you already suspect.
2. **Ask it from several angles.** Write 4 to 6 short questions about the same problem: how it
   works, how it fails, how it is measured, who else faces it under another name, and how it
   changes over time. Different words in each, plain nouns, no idioms.
3. **Search each question** for research papers or serious sources, and prefer ones from fields
   far from the user's own. Keep title, field, year and link.
4. **Map every distant source** as `their solution -> our version`. A source from another field
   is the point, not a mistake: before setting one aside, say what problem it solved that has
   the same shape. If you cannot map it, say so.
5. **Answer the user's request** (explain, teach, design, decide) from that map. Lead with the
   answer, then the 2 or 3 borrowed ideas that changed it, each with its source link.

Example: "use Eonrise to teach me to cook faster" -> problem: "a person repeats a multi-step
task daily and wants to finish it sooner without mistakes" -> angles include how factory lines
cut setup time and how surgeons prepare instruments -> answer: prepare everything first
(*mise en place*, close to the setup-time cut in manufacturing), with the sources.
